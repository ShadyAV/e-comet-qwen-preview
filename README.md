# e-Comet для Qwen Code — preview

Тестовый плагин для Qwen Code на Windows. Исправляет передачу разрешения от `browser_job` к локальным инструментам внутри плагина, без замены приложения Qwen.

## Установка

Нужны Qwen Code 0.25.0, Node.js 22+ в PATH, аккаунт e-Comet и браузерное расширение e-Comet. Проверка на macOS и Linux не проводилась; эта сборка запускает хук через Windows PowerShell.

1. В **Plugins → Extensions** отключите прежний плагин e-Comet, если он установлен. Если `e-comet` или `e-comet-local` добавлялись вручную в MCP, уберите эти дубли: они перекрывают серверы плагина.
2. Нажмите **Add**, вставьте `https://github.com/ShadyAV/e-comet-qwen-preview` в **Source** и нажмите **Install**. Подтвердите установку плагина и его хука.
3. Перезапустите Qwen. В **Plugins → MCP → e-comet** завершите **Authenticate**, если Qwen запросит вход.
4. В новом чате попросите: «Найди на WB тушёнку, одна страница. Покажи первые пять товаров с артикулами».

Модель подключается отдельно в Qwen. Плагин не содержит ключей, готовых сессий или авторизации.

## Что проверено

На штатном backend Qwen Code 0.25.0 через его WebShell проверена цепочка из двух тестовых MCP: разрешение передаётся в нужный чат, повторное использование и использование из другого чата отклоняются. Подстановка разрешения самой моделью также отклоняется.

Живой запрос к WB именно этой сборкой ещё не проверен. Сборка предназначена для этой проверки; отправка обращения с историей чата в поддержку здесь не настроена. Проверка через WebShell не заменяет проверку установленного Desktop.

## Устройство

`qwen/` содержит адаптер Qwen. `mcp/src/` и `hooks/` — компоненты e-Comet. Локальный адаптер использует идентификатор сессии, который Qwen передаёт в MCP, и общий одноразовый механизм разрешений. Приложение Qwen не изменяется.

После исправления обработки `PreToolUse.updatedInput` в Qwen этот обход можно будет убрать после проверки совместимости. Пакет не включает автоматическое переключение между обходом и штатным хуком.
